# Аналитика менеджеров и операционная дисциплина CRM

Read-only отчёты для руководителя: нагрузка, просрочки, зависшие сущности и качество ведения CRM.

## Назначение

Система отвечает на вопросы:

- чем занят каждый менеджер;
- где нет следующего CRM-дела;
- где просрочки;
- какие лиды/сделки без изменений;
- где систематически нарушается методология.

Автоматическое создание дел/задач и изменение CRM **не выполняется**.

Плановые сводки используют `crm_discipline_report` / `manager_workload` как источники (один обход, без повторного вызова workload из discipline). См. [scheduled-reports.md](./scheduled-reports.md).

## CRM-дела vs задачи

| Сущность | API | Роль в методологии |
|----------|-----|--------------------|
| CRM-дело | `crm.activity` | Следующий шаг по контакту/лиду/сделке |
| Задача | `tasks.task` | Отдельный трекер; не заменяет CRM-дело |

`OWNER_TYPE_ID`: лид = 1, сделка = 2, контакт = 3.

## Actions

| Action | Описание |
|--------|----------|
| `manager_workload` | Нагрузка и качество CRM по менеджерам |
| `leads_without_next_activity` | Лиды без следующего CRM-дела |
| `stale_leads_report` | Лиды без изменений более N дней |
| `stale_deals_report` | Сделки без изменений более N дней |
| `overdue_activities_by_manager` | Просроченные дела по ответственным |
| `crm_discipline_report` | Сводный управленческий отчёт |

## Качество ведения CRM (`qualityScore`)

Это **не KPI продаж** и не оценка эффективности сотрудника.

Формула (штрафы в процентных пунктах, итог 0–100):

```text
100
− % контактов без статуса
− % лидов без следующего дела (включая только просроченные)
− % сделок без следующего шага
− % просроченных CRM-дел среди активных+просроченных
− % зависших сущностей (лиды+сделки без изменений) среди активных
```

Рядом возвращается `qualityBreakdown` с расшифровкой штрафов.  
При недостатке данных: `qualityScore: null`.

## Просрочка и отсутствие следующего дела

- Берутся незавершённые CRM-дела (`COMPLETED = N`).
- Следующее дело: дедлайн сейчас/в будущем или без дедлайна.
- Только просроченные: есть незавершённые дела, но все с дедлайном в прошлом.
- Вообще нет дела: нет незавершённых activities у владельца.

Загрузка activities — **bulk** по типу владельца, затем map `ownerTypeId:ownerId` (без N+1).

## Зависшие лиды и сделки

Название отчёта: «без изменений более N дней».

Основание:

1. `DATE_MODIFY`
2. иначе `DATE_CREATE`

Это **не** точная длительность нахождения в стадии (история переходов не используется).

## Оптимизация контактов

`contact_quality_report` использует `collectContactQualityDataset()`:

- **1** полный обход контактов;
- общие счётчики и sample;
- один bulk activities для контактов;
- проверка цикла и ДР по индексу дел.

Ранее: 5+ полных обходов (~минуты на 4000 контактах).

## Лимит страниц

```env
BITRIX_ANALYTICS_MAX_PAGES=200
```

По умолчанию 200 (≈ 10 000 записей). При достижении:

```json
{
  "truncated": true,
  "warning": "Отчёт построен не по всем данным: достигнут лимит страниц."
}
```

## Права webhook

Bitrix24 → Разработчикам → Другое → Входящий вебхук:

- CRM (обязательно);
- Пользователи;
- Задачи (для метрик tasks).

Если Tasks нет:

```json
{
  "tasksAvailable": false,
  "warnings": [{ "code": "TASKS_ACCESS_DENIED", "message": "..." }]
}
```

Остальной отчёт продолжает формироваться (`partial: true`).

## Частичные отчёты

Необязательный источник (Tasks) не отбрасывает весь отчёт.  
Ошибки CRM activities для части сущностей отражаются в `warnings`.

## Производительность

- один проход контактов в quality/manager;
- bulk activities;
- кэш пользователей/компаний;
- sample ≤ 100;
- логи `[Analytics]` с `contactPasses`, `restRequests`, `durationMs`.
